# قصص المستخدم ومعايير القبول
# نظام UniFlow لإدارة الدراسات العليا

## 1. إدارة تسجيل الدخول

### User Story
بصفتي مستخدمًا مسجلًا في النظام، أريد تسجيل الدخول باستخدام بياناتي الصحيحة حتى أتمكن من الوصول إلى الوظائف المسموح لي بها.

### Acceptance Criteria
- يتم قبول بيانات الدخول الصحيحة.
- يتم رفض بيانات الدخول غير الصحيحة.
- تظهر رسالة مناسبة عند وجود خطأ.
- يتم تحويل المستخدم إلى الصفحة المناسبة بعد تسجيل الدخول.
- لا يمكن الوصول إلى الصفحات المحمية دون تسجيل الدخول.

---

## 2. إدارة الطلاب

### User Story
بصفتي موظف دراسات عليا، أريد إدارة بيانات الطلاب حتى أتمكن من متابعة بياناتهم الأكاديمية.

### Acceptance Criteria
- يمكن إضافة طالب جديد.
- يمكن عرض بيانات الطلاب.
- يمكن تعديل بيانات الطالب.
- يمكن البحث عن طالب.
- يتم التحقق من الحقول المطلوبة.
- لا يسمح بتكرار الرقم الجامعي.

---

## 3. إدارة طلبات القبول

### User Story
بصفتي موظف دراسات عليا، أريد إدارة طلبات القبول حتى أتمكن من متابعة حالة المتقدمين.

### Acceptance Criteria
- يمكن إنشاء طلب قبول.
- يمكن عرض طلبات القبول.
- يمكن تعديل بيانات الطلب.
- يمكن تحديث حالة الطلب.
- يتم التحقق من البيانات المطلوبة قبل الحفظ.

---

## 4. إدارة البرامج الأكاديمية

### User Story
بصفتي مسؤولًا أكاديميًا، أريد إدارة البرامج الأكاديمية حتى يتم تنظيم برامج الدراسات العليا.

### Acceptance Criteria
- يمكن إضافة برنامج أكاديمي.
- يمكن تعديل البرنامج.
- يمكن عرض البرامج.
- يمكن ربط البرنامج بالقسم المناسب.
- لا يسمح بحفظ البيانات المطلوبة بشكل ناقص.

---

## 5. إدارة المقررات

### User Story
بصفتي مسؤولًا أكاديميًا، أريد إدارة المقررات الدراسية حتى يتم تنظيم المقررات المرتبطة بالبرامج والخطط الدراسية.

### Acceptance Criteria
- يمكن إضافة مقرر.
- يمكن تعديل بيانات المقرر.
- يمكن عرض المقررات.
- يمكن ربط المقرر بالبرنامج أو الخطة المناسبة.
- يتم التحقق من البيانات قبل الحفظ.

---

## 6. تسجيل المقررات

### User Story
بصفتي موظف دراسات عليا، أريد تسجيل الطالب في المقررات حتى يتم توثيق مقرراته الدراسية.

### Acceptance Criteria
- يمكن اختيار الطالب.
- يمكن اختيار المقرر.
- يمكن تسجيل الطالب في المقرر.
- لا يسمح بالتسجيل المكرر لنفس المقرر.
- يتم حفظ عملية التسجيل في قاعدة البيانات.

---

## 7. إدارة المشرفين

### User Story
بصفتي موظف دراسات عليا، أريد إدارة المشرفين وربطهم بالطلاب حتى يتم تنظيم الإشراف الأكاديمي.

### Acceptance Criteria
- يمكن إضافة مشرف.
- يمكن تعديل بيانات المشرف.
- يمكن عرض المشرفين.
- يمكن ربط الطالب بالمشرف.
- يتم التحقق من صحة العلاقة بين الطالب والمشرف.

---

## 8. إدارة الأبحاث

### User Story
بصفتي مشرفًا أكاديميًا، أريد متابعة المقترحات والأبحاث الخاصة بالطلاب حتى أتمكن من متابعة تقدمهم البحثي.

### Acceptance Criteria
- يمكن إنشاء مقترح بحثي.
- يمكن ربط البحث بالطالب والمشرف.
- يمكن تعديل بيانات البحث.
- يمكن تحديث حالة البحث.
- يمكن عرض حالة البحث الحالية.

---

### User Story

### Acceptance Criteria

- يمكن تحديث حالة الرسالة.
- يمكن عرض بيانات الرسالة.
- يتم حفظ التغييرات في قاعدة البيانات.

### Acceptance Criteria

- يمكن تحديد موعد المناقشة.
- يمكن ربط اللجنة بالرسالة العلمية.
- يمكن عرض بيانات اللجنة.

---

## 11. إجراءات التخرج

### User Story
بصفتي موظف دراسات عليا، أريد متابعة إجراءات تخرج الطالب حتى أتأكد من استكمال متطلبات التخرج.

### Acceptance Criteria
- يمكن عرض حالة تخرج الطالب.
- يمكن متابعة متطلبات التخرج.
- يمكن تحديث حالة الإجراء.
- لا يتم اعتماد الإجراء عند وجود متطلبات ناقصة.

---

## 12. التقارير

### User Story
بصفتي مدير النظام أو موظف دراسات عليا، أريد استخراج التقارير حتى أتمكن من متابعة بيانات النظام.

### Acceptance Criteria
- يمكن عرض التقارير المتاحة.
- يمكن تحديد البيانات المطلوبة للتقرير.
- تظهر البيانات بشكل منظم.
- يتم منع المستخدم غير المصرح له من الوصول إلى التقارير.

---

## 13. إدارة المستخدمين والصلاحيات

### User Story
بصفتي مدير النظام، أريد إدارة المستخدمين والصلاحيات حتى أتحكم في الوصول إلى وظائف النظام.

### Acceptance Criteria
- يمكن إنشاء مستخدم.
- يمكن تعديل بيانات المستخدم.
- يمكن تحديد دور المستخدم.
- يتم تطبيق الصلاحيات حسب الدور.
- لا يستطيع المستخدم الوصول إلى الوظائف غير المسموح بها.

---

## 14. إدارة المستندات

### User Story
بصفتي موظف دراسات عليا، أريد إدارة المستندات المرتبطة بالطلاب والعمليات الأكاديمية حتى تكون الملفات منظمة ويمكن الوصول إليها عند الحاجة.

### Acceptance Criteria
- يمكن رفع المستند.
- يمكن ربط المستند بالعملية المناسبة.
- يمكن عرض المستندات المسموح بها.
- يتم التحقق من البيانات والملفات قبل الحفظ.
- لا يستطيع المستخدم غير المصرح له الوصول إلى المستندات المحمية.
